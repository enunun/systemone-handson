# Iteration 7：評価と，しきい値の選び方

Iteration 7で初めて使う概念を説明する．
コマンドの例は，devcontainerの中で実行した実際の結果である．

## なぜ評価するのか

テストは，プログラムが決めたとおりに動くかを確かめる．
しかし，判断エンジンの答えが正しいかは，テストでは確かめられない(Iteration 0から，テストでは判断エンジンを偽物にしてきた)．
モデルの答えの質は，正解がわかっている問い合わせを実際に振り分けて，測るしかない．

評価は，次のようなときに使う．

- 質問の文や選択肢の説明を変えたとき，良くなったか悪くなったかを確かめる．
- 人の確認に回すしきい値を決める．
- 判断エンジンを替える前後で(laya-serverから本家Jevへ，など)，精度がどう変わるかを比べる．

## 評価用のデータ

評価用のデータは，問い合わせと正解の部署の組である．
このハンズオンでは，`data/labeled.jsonl`に30件を用意した．

```text
{"subject": "Double charge", "body": "My card was charged twice for the same order.", "department": "billing"}
```

評価用のデータを作るときは，次のことに気を付ける．

- 実際に届く問い合わせに近いものを集める．判断しやすい問い合わせばかりだと，精度が高く出すぎる．
- 部署ごとの件数に偏りがあると，数の多い部署の結果に全体が引っ張られる．
- 質問の文を調整するのに使ったデータで評価すると，精度が高く出すぎる．調整用と評価用を分けておくとよい．
- 30件は，傾向を見るための小さな例である．1件の違いで正解率が3ポイント変わるので，細かな差は誤差の範囲になる．

## 正解率と，人の確認に回る割合

しきい値を決めると，問い合わせは「自動で振り分けるもの」と「人の確認に回すもの」に分かれる．
このハンズオンでは，次の2つの数で評価する．

- 正解率(accuracy)：自動で振り分けたもののうち，部署が正解だった割合．
- 人の確認に回る割合(review rate)：全体のうち，人の確認に回した割合．

しきい値を上げると，確信度の低いものから順に人の確認に回るので，正解率は上がりやすく，人の確認に回る割合も上がる．
2つは引き換えの関係にある．

## 混同行列

混同行列は，正解の部署(行)ごとに，判定した部署(列)の件数を数えた表である．

```text
actual \ predicted   billing   support     sales
billing                   10         1         0
support                    0        11         0
sales                      1         2         5
```

対角線(billing→billing，support→support，sales→sales)が，正しく判定した件数である．
対角線の外は，どの部署をどの部署と取り違えたかを表す．
この例では，salesの問い合わせを取り違えやすいことがわかる．
正解率という1つの数からはわからない，誤りの傾向が見える．

## しきい値ごとに評価する

しきい値を少しずつ変えて評価し，表にすると，しきい値を選びやすくなる．

```console
$ pnpm start eval --sweep data/labeled.jsonl
min-confidence  auto-routed  accuracy  review rate
0.0                      30      0.87         0.00
0.1                      25      0.92         0.17
0.2                      19      0.95         0.37
0.3                      17      1.00         0.43
0.4                      15      1.00         0.50
0.5                       8      1.00         0.73
0.6                       4      1.00         0.87
0.7                       3      1.00         0.90
0.8                       1      1.00         0.97
0.9                       1      1.00         0.97
1.0                       0       n/a         1.00
```

しきい値は，次のように選ぶ．

1. 自動で振り分けたものに許せる誤りの割合を決める(例：誤りは5%まで)．
2. その正解率を満たすしきい値のうち，人の確認に回る割合がもっとも小さいものを選ぶ．

上の表で「正解率0.95以上」とするなら，しきい値0.2が選ばれる．人の確認に回るのは37%である．
「誤りを許さない」なら0.3で，人の確認に回るのは43%になる．

判断エンジンや質問の文を変えたら，この表を作り直してしきい値を選び直す．
本家Jevへ切り替える前に同じデータで評価しておけば，切り替えた後と比べられる．

## 小数の割り算と表示

正解率は，件数の割り算で求める．
自動で振り分けたものが0件なら，割る数が0になる．
JavaScriptでは`0 / 0`は`NaN`になり，エラーにはならない．
値がないことは`undefined`で表し，表示するときは`n/a`とする．

表の列をそろえるには，`padStart`(左に空白を詰める)と`padEnd`(右に空白を詰める)を使う．

```ts
"8".padStart(5); // "    8"
"sales".padEnd(8); // "sales   "
```
